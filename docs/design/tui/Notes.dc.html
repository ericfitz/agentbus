agentbus tui · design notes
Observe and participate. One binary, no server: the TUI opens the SQLite database through the bus package exactly like status and reset do, registers as the human, and is an ordinary bus participant. Bubble Tea + Lip Gloss; static mockups, 100×32 cells at zoom 1.
data flow
start Register(tui_name, resume) → ListChannels → Subscribe(all) → History(selected, last 200) live goroutine: Receive(wait=receive_max_wait_seconds, ack=prev token) → tea.Msg per batch gaps[] → dim “n evicted” divider in the stream; unread = seq > last-seen per channel status every 5 s: StatusReport() → status bar + Health overlay send Enter → Send{channel, content, reply_to?}; memory channel → Send creates a memory search Search{query, mode, count 20}; semantic_unavailable → “text only” badge, no error memories Search{channel, mode text, count 200} for the list · GetMemory / EditMemory / DeleteMemory scroll at top of stream → History(before=oldest seq, 200) prepended quit Close() waits for heartbeat and tick goroutines, as mcp does

color rules (ANSI-safe, honors the terminal palette)
cyan agent sender names, selected channel, key hints, focused overlay border amber the human’s own name and messages, warnings (text-only fallback, capacity) green live heartbeat dot, ok states, Health border magenta memory channels (◆) and the Memories overlay border red errors and delete confirmation dim timestamps, contexts, dividers, help text · never color message content
bus and config additions needed
config tui_name (string, default OS user name, same rule as register names); flag --as overrides status StatusReport already has sessions, channels, usage, budget, notice, backlog, paths. Health also wants: embedding endpoint + model + last query outcome, last receive batch time, gap count. First three come from config and the TUI’s own call log, so no bus change; “last tick” is the only new StatusReport field and is optional. history unchanged; the TUI pages with before=oldest seq cli new subcommand agentbus tui in main.go; internal/tui package; ~4 Charm dependencies
out of scope for v1
Mouse support · multiple humans in one TUI · editing config values in-place (o opens $EDITOR) · reset from the TUI (keep it a deliberate shell command) · light-theme tuning beyond ANSI defaults
